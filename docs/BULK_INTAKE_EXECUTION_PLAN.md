# 題庫批量生產線：先規劃，再擴量

## 目前基線與瓶頸

- 公開課程目錄有 61 個課題入口；準備中入口不代表已有題。
- 來源清單有 951 條記錄，含容器／內含項目，不能當成 951 份獨立原卷；清單快照未全面點清題數。最新進度須合併 registry、批次帳冊及正式題庫，不能單讀舊 inventory。
- 已有：來源 SHA、提取快取、穩定 ID、五項審核、重複候選、交易備份、共用題面預覽與發布檢查。
- 瓶頸：題界與內容仍逐卷整理；裁圖與數學檢查仍有來源專用腳本；分類理由與難度校準未成統一批量規範；每小批重跑大量發布檢查。
- 本輪沒有新增題目，也沒有改動學生進度或網站設計。

## 目的與取捨

學生須能按「課程 → 課題 → 子分類 → 主要技巧」找到合適練習，並按難度循序進階。內部流水線須可重跑、可修訂、可定位原題；不能以快速增加題數換取錯圖、漏題或不可追查的答案。

不再以「一份 PDF 一個新程式」作為常規。共用引擎處理來源；來源差異放在資料 manifest、裁圖座標與驗算規格。只有確實出現新格式，才擴充共用能力。

## BULK-01：一次整理來源與排隊（待處理）

1. 合併來源清單、已登記版本、現有 intake 與 canonical provenance，形成唯一工作佇列。
2. 區分原卷、答案卷、PDF／Word 配對、重複檔案及容器內項目；配對候選必須確認，不能僅憑檔名合併。
3. 記錄可讀文字／掃描／混合、頁數、答案來源、有圖與否、課程及候選課題。未知題數顯示「未點清」。
4. 優先選已有完整答案、結構清楚、同格式可連續處理的來源；有問題的題單獨入待辦，不阻塞其他已驗收題。

交付：可按來源、課題、格式、阻塞原因查看的批次佇列；現有已入題來源不再重做。

## BULK-02：先固定分類與難度規則（待處理）

分類欄位分開保存：

| 欄位 | 用途 |
| --- | --- |
| 課程 | Core／M1／M2，另記適用年級 |
| 課題／子分類 | 知識範圍，沿用既有穩定 ID |
| 主要技巧 | 決定解法的核心步驟，一個主技巧 |
| 次要技巧／先備知識 | 支援跨課題搜尋，不重複刊登同題 |
| 題型 | MCQ、短答、多小問、證明等，與難度分開 |
| 難度與理由 | 用解題推理校準，不以題長、來源名稱或 MCQ 判斷 |
| 來源層級 | 原卷／教科書／例題等，與難度分開 |

首版沿用現有 easy／medium／hard，避免未校準就擴成更多假精細等級：

- 基礎：直接辨認或使用單一方法，無額外條件分支。
- 進階：需要連接步驟、轉換表示或結合兩項知識。
- 挑戰：隱藏限制、參數消元、多種情況、可行根／邊界檢查或較深證明。

先用現有各課題代表題建立校準樣本；同時記錄預估步驟、條件分支及理由。未解完不能僅憑外觀給最終難度。多小問題保留各小問難度，整題記錄實際必需推理，不能因有大量例行小問就升級。

新技巧先列候選，與同義既有技巧比較後再批准，避免「同一方法，多個名稱」。

交付：分類字典、難度校準樣本、機器檢查報告及人工覆核清單。

## BULK-03：共用批量管線（待處理）

固定流程：**來源登記 → 批量提取 → 原題定位 → 標準草稿 → 分類／解答／圖像 → 分項覆核 → 對帳 → 匯入 → 合批發布**。

- PDF／Word／HTML 使用不同提取入口，但輸出同一標準草稿；同 SHA 的頁圖及文字只生成一次。
- 先批量建立原題定位；跨頁、A–D 圖選項及全部小問必須完整列入。
- 翻譯、分類及解答可批量產生草稿，但草稿與已驗收內容明確分開；不得用規則自動蓋五項通過。
- 圖片使用共用裁圖工具與來源 manifest；專用座標是資料，不再複製整套裁圖程式。原圖、題圖、解析圖分開。
- 同類題可共用驗算方法，例如多項式代入、數列條件或線性規劃頂點；每題仍保留獨立輸入、結果及適用限制。
- 相同來源重跑不加重複題；來源改版保留學生 ID，重審受影響欄位。來源 SHA 改變仍須重新確認對應關係。
- 分類／答案／圖像／學生畫面使用現有 fingerprint 審核失效機制；不可用舊 QA 代替改題後驗收。

先補現有工具缺口，不重建第二套管理系統。尤其要處理 `pipeline.apply()` 與新公開課程目錄生成的整合：目錄更新必須納入可回復發布流程，避免題已上架但入口數字過時。

## BULK-04：教科書來源規格（待處理）

保留出版社、書名、版次／年份、冊別、章節、練習名稱、印刷頁碼、PDF 頁碼、原題號及小問。未提供的資料保持未知，不猜測。

題目 ID 不以顯示次序生成；同版修訂保留定位，異版使用版本關係追蹤。版次不同不自動視為重複；確認題幹、數值、圖與所有小問後才連結 canonical ID，並保留各來源。

例題及練習題獨立標籤。只有題目而沒有解答的來源進入待解答隊列，不能標為已核實完整解答。

## BULK-05：試產與擴量（待處理）

先選三類來源測試：可讀文字題、掃描多圖題、教科書或最接近教科書編排的來源。Oxford LP 可作掃描題候選；未開始匯入的草稿不計新增。

首輪以約 30–50 條來源題為目標工作量，實際按完整原題邊界調整。這是試產規模，不是速度承諾。每題跑完整流程，再用同工具處理下一份來源，確認不用新增專用 importer。

記錄每階段實際時間：提取、轉錄、分類、解答、圖像、覆核、發布。用完整通過題／工作時間衡量產能，另報返工率與待補率；不以生成草稿數當產能。測量後才訂每批目標及預計完成時間。

擴量以同格式來源成組；高圖量／缺答案來源另排，避免拖慢已可完成的工作。逐題完整驗收保留；全站回歸及部署合併至發布批次執行。共用 renderer 或 schema 改動時重跑相應全套測試。

## 發布資格及每輪報告

每條原題歸入新增、修訂、確認重複或具體待補之一。來源題數與獨立題數分開；未點清不能報零，也不能計完成百分比。

發布須通過：雙語題文／選項、主要技巧／難度理由、獨立答案檢查、同題圖像 QA、共用學生題面與來源對帳。圖像規則沿用全域 DIAGRAM_IMAGE_QA_WORKFLOW。

每輪報告固定列：

1. 本輪處理來源及確認原題數。
2. 新增／修訂／重複／待補數量，待補原因。
3. 分類與難度覆核結果。
4. 本機驗收與正式發布狀態，附證據。
5. 階段耗時、返工原因及下一批。
