# EAC 全課程結構與一致模板

版本 CUR-20261028（結構批次快照）· 當批目標：先理解指定來源，建立可持續加題的結構；未開始把這批 PDF／Word 當成已驗收題目上架。

## 1. 從學生的目的出發

學生進站不是為了瀏覽檔案清單，而是知道「今日溫哪一課、卡在哪一步、做完之後做甚麼」。結構要支援四個入口，但日常畫面只突出一個主要動作。

| 學生當下目的 | 預設路徑 | 結果與下一步 |
|---|---|---|
| 跟進剛上完的一課 | 選課程／年級 → 課題 → 做 5 題 | 先做、再看解法；最後重做該組錯題 |
| 某種方法不明白 | 課題 → 小節 → 解題技巧 | 看第一眼訊號、必要概念及同技巧小組 |
| 考試前測試自己 | 已學課題 → 混合組題／自測 | 自動評分及書寫自評清楚分開，不將自評混入準確率 |
| 接續學習 | 續做／錯題／收藏 | 保留原題號、答案草稿及次序，不因重新匯入而清空 |

未來的課程選擇是額外導航維度，不增加另一套試用版、課題版、報告版入口。原有「選課 → 做題 → 核對 → 重做」仍是主線。M1／M2 未有足夠已驗收內容及課程篩選前，不顯示無法作答的按鈕。

## 2. 四種不同的資料不能混在一起

```text
課程 track：Core / M1 / M2
  → 年級／來源階段：S1…S6；M1、M2 不等於 Form 7/8
  → 數學範疇 area：代數、幾何、統計、微積分等
  → 課題 topic：穩定容器
  → 小節 subtopic：學生能理解的概念／問題群
  → 主技巧 primary skill：這題第一個決定性的解題方法

獨立篩選：題型、難度、用途、語言、已做／未做／錯題／收藏
獨立來源：檔案、版本、學校／年份、頁碼、原題號、答案及題圖
```

- **年級不是課題的所有權。** 百分數、度量、多項式、統計會跨年級出現；同一容器有階段、小節及逐題的建議程度，不複製六套題庫。來源放在 S1 不代表每題只屬 S1。
- **課程需要分開。** 必修、M1、M2 的同名微分／概率／二項式不直接合併；學生所學範圍及題目深度不同。先備知識可跨課程引用，練習及記錄仍按題號／課程辨識。
- **mock by topic 是來源集合。** 裡面同時有 DSE 標籤、學校 mock 及混合卷，不是一個「Mock 科目」，也不能把檔名當已核實官方來源。
- **小節不是難度。** 同一技巧可有基本及綜合題；不使用一條六層階梯製造大量空分類。
- **主要技巧只有一個。** 綜合題以主導方法歸類，跨課題加標籤。不能因題中有直線就歸直線，也不能因最後答案是圓就歸圓方程。

61 個課題容器按來源初步整理：Core 42、M1 9、M2 10。小節是**候選教學切分**，不是已提取的題型或官方課綱認證。每項有學習目的及建議先備關係；先備關係只供導航提示，不鎖住學生自行選課。完整雙語清單見 [來源／課題矩陣](planning/SOURCE_INVENTORY.md)；機器資料見 [curriculum.json](../content/planning/curriculum.json)。

## 3. 本次真正看到了甚麼

九個指定資料夾共 928 個實體檔案：597 PDF、329 DOCX、2 ZIP；另外盤點 ZIP 中的 23 個成員。這不是題目數。

- 57 個初中／高中來源資料夾規則，另有 M1／M2 及 mock 檔名候選路由。全部檔案都記錄 SHA256 及固定 source ID，沒有略過無法分類的合集。
- 324 組同名 Word／PDF 只是配對候選，可能有答案版、版本差或公式差異，不能直接當一份。
- 23 個 ZIP 成員全部與已解壓檔案位元組相同；另有 3 個實體重複副本。保留來源別名，不重複匯題。
- 328/329 份 Word 有媒體；部分題文／公式不在普通文字節點。237 個代表摘錄中 160 個過薄或主要只見題號／答案。文字薄不等於題目壞或沒有題。
- 已用 PDF 渲染確認 APGP 第一頁及 M1 probability distribution 第一頁：原頁有完整題文，而 Word 普通抽文不完整。這是**來源結構抽查**，未驗算這兩頁題目，也不是學生題圖驗收。
- S5 transformation 有一份 M1 differentiation，與 M1 資料夾副本完全相同；M2 matrix reviews 的代表文字混有根與多項式。已記風險，不用資料夾名稱替代逐題理解。

本次並未聲稱讀完 597 份 PDF 的全部頁面。已做的是完整檔案盤點、代表文字開首檢視、兩個原頁視覺抽查及可持續的資料結構。逐題範圍、答案及題圖覆核是下一階段工作。

規劃檔留在 `content/planning/`，不進 `src/`，不增加學生下載量，也不顯示 61 個空入口。現有題庫仍按需讀取有上限的分片，數萬題不改成一個巨大 HTML 或一次下載全部解答。

同一來源路徑的 source ID 固定，內容 hash 用來追蹤版本；路徑改名要登記別名，不能當新題。每條題之後另保留原檔、頁碼／章節、原題號和版本。檔案位元組相同不代表題目層的跨卷重複已全部找出；真正合併題目仍比較題幹、條件、選項、圖及答案。

## 5. 既有題庫及資料介面

七個既有課題綁定原 `topicId`／`chapterId`，包括 `polynomial`／`polynomials` 及 `mensuration`／`mensuration-core` 的差異，不能只按新名稱重建；既有 subcategory 及 skill ID 亦以 canonical catalog 為準，候選小節不能直接取代它們。1,186 題、所有舊 ID、別名及學生紀錄保留；本次新增題數為 0。

新來源先逐題形成審稿記錄，再經現有 JSON importer 的 preview、內容驗證及 build。審稿記錄至少要有：

| 欄位 | 用途 |
|---|---|
| sourceId + SHA256 + 原檔／頁碼／原題號 | 找回同題證據，不以顯示次序配對 |
| trackId + stageEvidence | 課程及程度分開，不由資料夾直接猜建議最低年級 |
| topicId + subcategory + primary skill | 主解題目的；小節與技巧確認後才寫入已上架 catalog |
| conceptId + first-look + prerequisite skills | 將「怎樣開始」連到教學指引，缺概念就先補概念 |
| secondary tags + format + difficulty + role | 跨技巧、題型、難度、上堂／功課／挑戰各自獨立 |
| bilingual question + options + solution status | 不把來源簡答冒充完整詳解；不憑空補條件 |
| diagram references + labels/data + review evidence | 題圖與答案圖分開；全圖選項、刻度、單位及原題一致 |
| answerCheck + classificationReview + status | 記錄核查方法與結果，不能只寫 pass |
| canonical ID / existing ID / duplicate aliases | 修訂沿用 ID；確認同題後才合併來源 |

**M1／M2 有一個真正的架構依賴：** 現有 runtime 只有 Form 1–6 的 `minForm` 篩選，沒有獨立課程欄位。不能用 Form 6 冒充 M1／M2。發布前須把 course 欄位加到 canonical validator、metadata index、search shards、組題 URL、active-set snapshot、個人偏好及匯出，保留舊 core 記錄的相容預設；測試 core 不會抽到 extended 題，M1 不會抽到 M2。這項列為 CUR-06 待處理，今次沒有假裝已實作。

## 6. 模板一致性的約束

本次用數學筆記技能的教學分類方法；網站沿用現有已認可風格，不套入 PDF 的藍青模板。

- **視覺骨架：** 炭黑封面、淺色紙面 `#f8f8f7`、正文 `#282b30`、克制灰藍 `#404e5b`；新課題不自行加金／綠主題，也不建立一份獨立全站 CSS。
- **字體：** 英文展示字沿用 `--study-display`，中文題文、說明及控制沿用 `--font-stack`；公式仍用本地 MathJax SVG，不用普通字體仿公式。
- **題面：** 同一雙語段落／表格／多圖 renderer；短題自然收緊，長題依內容展開；四周表格框線完整，數值靠左。原題顏色有數學意義就保留，裝飾色不可改壞題意。
- **教學節奏：** 辨認 → 條件翻譯 → 單工具 → 工具連接 → 限制陷阱 → 逆向判斷 → 綜合挑戰。這是編排目標，不能在未核查題庫上虛構「已掌握」百分比。
- **互動：** 參數名／值、播放／暫停、重設一致；手動即暫停、本次模式狀態保留、離屏停止、減少動態可靜態探索。新課題必須明確配對已驗算場景，否則先用一致的靜態數學符號；不能把所有未知課題都套四心動畫。
- **觸控及鍵盤：** 目標控制至少 44px；不以 hover 作唯一入口；動畫集中在導覽／概念區，避免干擾作答。
- **容許不同內容：** 統計有圖表／幹葉 key，幾何有準確圖與證明，微積分有長推導；共享字體、邊界及操作，不強迫所有課題變成同一高度的卡片。

[template-contract.json](../content/planning/template-contract.json) 記錄共享資產、閱讀／評分規則、四寬驗收及禁用的無關動畫 fallback。這份契約用於**將來新課題的驗收**；它並不表示所有歷史 UI 問題已修完。[完整 UI／UE 待辦](UI_UX_ROADMAP.md) 繼續保留。

## 7. 等甚麼，以及為何要等

沒有必要先請你重新命名或搬動 928 份檔案。現有來源足夠開始以下內部工作；「待處理」主要是我們要做的覆核，並非全部要等你補資料。

| 固定工作號 | 狀態 | 下一個實作／驗收條件 | 為何需要 |
|---|---|---|---|
| CUR-01 | 完成 | 檔案對帳、hash、壓縮重複、摘錄及原頁抽查見本次證據 | 知道來源到底有甚麼，避免漏卷及重複匯入 |
| CUR-02 | 完成 | 61 課題、先備圖、七個綁定及生成輸出通過測試 | 後續批量加題仍用同一結構 |
| CUR-03 | 處理中 | 對每份來源定位題界、原題號；每題有主技巧／來源／題圖需求 | 檔名及抽文不能當完整理解 |
| CUR-04 | 處理中 | 先擴充現有七課；同題對照、修訂原 ID、獨立核算答案 | 較快把新來源接到已驗收流程，減少額外 UI 變數 |
| CUR-05 | 待處理 | 按先備鏈建立初中基礎，再進階至三角學、函數、概率等 | 學生能由較簡單入口開始；不是按資料夾字母排序 |

## 8. 驗收與後續維護

新增分類、映射、來源或先備關係後，先執行：

```sh
python3 scripts/inventory-curriculum.py '/本機/By topic Review materials'  # 來源變動時才重掃
node scripts/build-curriculum.cjs
node scripts/build-curriculum.cjs --check
node scripts/build-content.cjs --check
node --test tests/*.cjs
```

CI 直接使用已提交來源快照，不需要訪問本機 Downloads。`--check` 驗證生成路由及文檔沒有過期，測試額外阻止課程混用、無效先備鏈、假題數及錯誤舊 ID 綁定。今次沒有修改學生 HTML、CSS、JS 或題目，不把新一輪 4 寬視覺／全題數學驗算寫成完成。所有實際測試只記在 [本次 QA](qa/2026-10-28/curriculum-intake/README.md) 及 [IMPLEMENTATION_LOG.md](IMPLEMENTATION_LOG.md)。
