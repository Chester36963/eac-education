# 題目 Agent 與網站 Agent 交接規格

2026-11-11。狀態：交接規格已建立；尚未建立或派遣另一個 Agent，未新增題目。

目的：內容整理與產品開發同步推進；正式題庫由單一整合者套用，避免重複題、分類分歧、學生 ID 改變及互相覆寫。

## 分工與工作隔離

- 內容 Agent：按分配來源點清題數、定位、轉錄、雙語、分類、解答、圖像及逐項 QA，交付可匯入批次。
- 網站 Agent／整合者：共用 schema、分類字典、renderer、學生與家長流程、管理工具、匯入交易、正式回歸與 main 發布。
- 內容 Agent 使用獨立 worktree 及 `codex/content-<batch-id>` 分支。來源 PDF／Word 可唯讀共用；草稿、快取、管理服務及預覽埠各自獨立。不能兩個服務同時使用預設 4174 或同一可寫 registry。
- 每批建立領取紀錄：batch ID、負責 Agent、來源相對路徑、來源 SHA256、課程／課題、基準 commit、狀態、產物位置。原題數未知填 null／未點清。相同來源 SHA 不重複領取；若拆卷，明確列原題號及跨頁歸屬。
- 內容 Agent 不直接改 main、canonical chapters、公開 src/data 或共用分類字典，不套用、不推送正式站。新分類以批次 catalog／skills 提案提交整合者處理。

## 必讀與既有工具

以各自 worktree 根目錄解析以下相對路徑：

1. `docs/EDITOR_OPERATIONS.md`：已存在的本機管理流程、交易、來源改版與審核失效。
2. `docs/CONTENT_SCHEMA.md`：canonical 欄位、contentBlocks／solutionBlocks、穩定 ID、來源與 alias。
3. `docs/BULK_INTAKE_OPERATIONS.md`：最新四級難度與難度理由要求，優先於舊執行規格內三級描述。
4. `docs/BULK_INTAKE_EXECUTION_PLAN.md`：批量策略；當中待處理項目不當作已實作。
5. `/Users/chester/.codex/DIAGRAM_IMAGE_QA_WORKFLOW.md`：同題圖像、獨立資產與實際學生畫面 QA。

沿用 `content/intake/editor/` 的現有批次模型，不另造 JSON schema／專用 importer。啟動與預覽命令見操作手冊。`scripts/import-questions.cjs` 預覽亦會驗證資產路徑；跨 worktree 交付須連同資產對應根目錄，不能只交 JSON。生產套用以現有工作台交易流程處理，非直接執行低階 importer --apply。

## 首批與擴量

首批一個課題、明確來源、約 30–50 條完整原題；原題邊界優先於硬湊數量。先比對已上架 canonical、來源別名及 intake 帳冊，再整理真正缺題；不可將差額直接當成缺題。先交少量完整樣本確認格式及分類，其餘可同步完成來源定位與提取。以驗收通過且可發布題數／實際時間衡量產能，不以草稿數計。

目前 ASGS 三份 PDF 已有大部分題入庫，宜先作對帳或既有流程示範，不能整卷再次新增。牛津來源雖有 inventory，但尚未接入多 collection 的可匯入 registry；在整合者完成允許根目錄接入前，只可整理來源及草稿，不能聲稱整套匯入已可用，也不可放寬管理服務為任意檔案存取。

## 每批必交產物

- 批次 JSON：沿用現有 intake schema，保留來源定位及穩定學生 ID。
- 原題 ledger：每個原題號、小問／跨頁範圍 → 新增、修訂、確認重複或待補；新／舊 canonical ID、處置原因逐項列明。總原題數與獨立題數分開。
- 分類：Core／M1／M2、適用年級、課題、子分類、主技巧、次要知識、題型、四級難度及根據完整解法的 difficultyReason。缺少技巧時交提案，不自行改全站。
- 答案檢查：原答案來源、獨立推導、可行根／定義域／單位等檢查；來源簡答與完整解答分開標示。
- 題圖／解析圖：可編輯 SVG 或已核對裁圖，來源 SHA／頁碼／原題號／裁圖座標或重建依據；所有 A–D 圖選項完整。原始卷及整頁快取不放公開 src。
- QA：文字、分類、數學、圖像、學生畫面五項實際證據。自動格式通過不等於數學或圖像已核實；未做的審核保持待驗收。
- 交接摘要：基準 commit、變更檔、已確認題數、新增／修訂／重複／待補、具體阻塞、耗時、測試命令／結果與資產位置。大量快取留本機；交接須包含必需發布資產與精簡審核證據。

## 整合者接收後

1. 對照 main 最新版、來源 SHA、分類及穩定 ID；先處理分類提案，檢查跨批重複與來源改版。
2. 搬入批次及資產到受控 staging，重新驗證路徑與題數。新基準或資產／題文改變後重做受影響審核，不沿用失效 QA。
3. 預覽差異；透過工作台交易備份套用，保留回復與批次收據。
4. 檢查內容／課程 build、公式殘留、圖像、學生實際預覽、搜尋／組題／作答／收藏／續做及舊記錄相容；UI 四寬度 320／390／768／1440px。
5. 合批 main commit／push；等待 Deploy 及 Pages 成功，核對正式 revision、資產 SHA 與實際作答。報告分清草稿、可匯入、本機套用及正式上架。
